## 第 1 天：Git 与 GitHub

### 1.1 先搞懂 Git 在干什么（30 分钟）

    工作区                暂存区              本地仓库            远程仓库
  (你改的文件)  --add-->  (准备提交)  --commit--> (历史记录)  --push--> (GitHub)

三个概念：仓库（文件夹+历史）、提交（带说明的快照）、分支（独立开发线，现在只用 main）。

**资源**：B 站搜「Git 入门 尚硅谷」或「廖雪峰 Git 教程」，
**只看前 40 分钟**：init / add / commit / push / clone。
不要学 rebase、stash、submodule，现在学只会劝退。

**怎么学**：看 5 分钟，立刻在自己项目里敲一遍。Git 是手感技能。

### 1.2 配置身份

VS Code -> Terminal -> New Terminal：

    cd C:\Users\Administrator\Documents\deepseek-harness\default-workspace\engine-phm-study
    git config --global user.name "你的名字"
    git config --global user.email "你的邮箱@qq.com"
    git config --global core.quotepath false
    git config --global --list

### 1.3 注册 GitHub 并建空仓库

1. https://github.com 注册（用户名认真取，以后写简历）
2. 右上角 + -> New repository
3. Repository name: engine-phm-study
4. 选 Public
5. **三个勾选框全部不要勾**（README / .gitignore / license，本地已有）
6. 复制地址：https://github.com/你的用户名/engine-phm-study.git

### 1.4 提交并推送

    git init
    git branch -M main
    git status          # 先看 Git 认为哪些文件有变化（养成习惯）
    git add .
    git status          # 关键：确认列表里没有 .venv/ 和 data/raw/
    git commit -m "chore: 初始化项目骨架与环境配置"
    git remote add origin https://github.com/你的用户名/engine-phm-study.git
    git push -u origin main

第二次 git status 是最关键的一步。看到 .venv/ 就停下，先解决再继续。

### 1.5 验收
- [ ] GitHub 上能看到仓库
- [ ] 首页正常显示 README
- [ ] 仓库里没有 .venv，没有 data/raw 的数据文件
- [ ] git status 显示 working tree clean

## 第 2 天：跑通环境，读懂自己的代码

### 2.1 环境自检

    cd <项目目录>
    .\.venv\Scripts\python.exe scripts\check_env.py

期望每个包都是 [OK]，最后一行「全部依赖就绪」。

| 现象 | 原因 | 解决 |
|---|---|---|
| 禁止运行脚本 | PowerShell 执行策略 | Set-ExecutionPolicy -Scope CurrentUser RemoteSigned |
| pip 下载慢 | 走国外源 | 加 -i https://mirrors.aliyun.com/pypi/simple/ |
| torch import 失败 | 用了 Python 3.14 | 必须用项目内 .venv（3.11） |
| 中文变方框 | 缺字体配置 | 用 src/utils.py 的 setup_chinese_font() |

### 2.2 配置 VS Code
1. File -> Open Folder 打开项目
2. Ctrl+Shift+P -> Python: Select Interpreter -> .\venv\Scripts\python.exe
3. 装扩展：Python、Pylance、Jupyter、GitLens
4. 新建终端确认提示符前有 (.venv)

### 2.3 读懂代码（今天最有价值的一小时）

| 文件 | 要理解什么 |
|---|---|
| src/utils.py | 为什么用 Path 而不是拼字符串？PROJECT_ROOT 怎么算出来？ |
| src/utils.py::setup_chinese_font | 为什么设 axes.unicode_minus = False？ |
| src/data_loader.py | CMAPSS_COLUMNS 里 21 个传感器怎么命名？为什么不写死路径？ |
| src/data_loader.py::describe_dataframe | 为什么拿到新数据先跑一遍体检？ |
| src/features.py::time_domain_features | 峰值因子为什么对故障冲击敏感？ |
| src/features.py::freq_domain_features | 重心频率 FC 的物理含义？ |

**动手改一处**：给 time_domain_features 增加 "variance": float(x.var())，验证不报错。

### 2.4 提交
    git add .
    git commit -m "feat: 补充时域方差特征"
    git push

## 第 3 天：第一份数据探索报告

### 3.1 数据：CWRU 轴承
搜索 "CWRU Bearing Data Center"，下载 12kHz Drive End 的 4 个文件：
Normal_0.mat（正常）、IR007_0.mat（内圈）、OR007@6_0.mat（外圈）、B007_0.mat（滚动体）
放到 data/raw/cwru/。

**没下载也能跑**：notebook 会自动切换到合成信号，先把流程走通。

### 3.2 打开 notebooks/01_cwru_explore.ipynb
内核选 Python (phm) 或 .venv 的解释器，从上到下执行。

### 3.3 要回答的 5 个问题
1. 四类信号幅值有明显差别吗？RMS 谁最大？
2. 峭度对哪种故障最敏感？为什么？
3. 峰值因子和 RMS 是同一件事吗？
4. 光看时域能区分内圈和外圈故障吗？不能的话需要什么工具？
5. 只能选一个特征你选哪个？局限是什么？

### 3.4 沉淀报告
照 results/reports/01_cwru_data_report_template.md 填，写到
results/reports/01_cwru_data_report.md。

第 3 天验收：notebook 从头跑通 / 有对比图 / 有特征表 / 能回答第 4 问 / 已 push。
